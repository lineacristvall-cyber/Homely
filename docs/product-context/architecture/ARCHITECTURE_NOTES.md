It follows the [current product decision record](../CURRENT_CONTEXT.md), [screen/state specification](../SCREEN_STATE_SPEC.md), [v3 UI decision flow](../flows/Homely-UI-Decision-Flows-v3.drawio) and concept screens, especially room/voice `01`, product evidence `06`, actual-product placement `07`, and decision `09`. ## Core boundary

Homely owns the canonical project, user corrections, consent, original room assets, measurements, exact product/variant record, source evidence, job/event history, render lineage, comparison, hard-cap decision and purchase-status ledger. A provider receives only the minimum inputs needed for a capability request. Its conversation history or generated prose is never the sole source of project truth. A swappable adapter maps provider-specific requests and results to typed Homely contracts. This permits future Claude or other models **only for capabilities they actually support**, after rights, privacy, quality, latency and cost checks; no assumption that every vendor can create images, stream speech or verify retailer stock.

The router config is versioned per capability (`text_extract`, `reason_compare`, `image_edit`, `transcribe_turn`, `voice_live`, `speak`, `source_query`). Each route records provider, exact model ID, prompt/schema version, timeout, budget, fallback, data policy and release cohort. Jobs pin the route version at start. A model swap changes the adapter/config, then passes replay and canary gates before promotion. Provider output remains a proposal or artifact until deterministic app-owned checks accept it.

## Contracts that preserve truth

| Contract | Required fields and rule |
| --- | --- |
| `CapabilityRequest` | `capability`, `project_version`, `consent_scope`, `asset_refs`, `schema_version`, `deadline`, `max_cost`, `idempotency_key`, `route_version`. Reject missing consent or disallowed use before vendor calls. |
| `CandidateVariant` | Product identity, exact SKU/finish/size, condition, dimensions, required quantity, seller/location, product image source and permitted-use status. A title or similar-looking image is insufficient identity evidence. |
| `AvailabilityObservation` | Exact SKU, quantity, fulfillment region/method, source URL or record, verification method, observed time, freshness policy and expiry. Listing presence alone routes to S12 lead. Stale or mismatched evidence leaves the ready lane. |
| `DeliveredCost` | Item total, delivery/pickup, tax, fees and relevant restoration/assembly, currency and estimated-vs-confirmed status. A hard cap is checked against the *all-in* amount; unknown required components block a confident under-cap claim. |
| `RenderResult` | Original room image ID, exact SKU image refs, transform/geometry version, renderer/model version, generated asset, identity check, geometry check and `illustrative` disclosure. The composite cannot establish measured fit. |
| `JobEvent` | Queued/running/partial/needs-input/completed/failed/cancelled, actor, time, version and correlation ID. Cancel stops future work and attempts provider abort; a late result cannot overwrite a cancelled or newer project version. |
| `UsageEvent` | Provider/model/route, input/output tokens or audio minutes/image tokens/tool calls, actual billed cost where available, project/session IDs, reservation and refund adjustments. |

Source connectors must be authorized and obey rate/usage limits. Marketplace and retailer access is an open validation gate, including Facebook Marketplace, Craigslist and eBay. The app does not infer six available chairs from one active listing. Before S17 seller handoff, S16 rechecks exact variant, six-unit availability, delivery and price; any failure returns to S18/S14 with the old decision kept in history. Seller checkout is external and a click never means purchased. Affiliate credits depend on contracted, eligible, realized proceeds and reversal rules.

For S13, keep original and product-source images visible beside an illustrative composite. Image editing should preserve the exact variant’s silhouette, material, finish and plausible perspective, but independent numeric checks handle chair arm clearance, seat/table heights, circulation and scale uncertainty. Missing floor geometry or product dimensions yields `needs input`; low identity confidence falls back to source image and measurements. Rerun a swap from the newly selected SKU, not a retouched previous result. Validate with real room/SKU fixtures before any fidelity claim.

## Current OpenAI model choices and cost logic

This is a **2026-09-13 snapshot from official OpenAI documentation**, not a promise of account-specific access or stable future prices. The user’s “image gen 2.5” maps to two documented API model IDs, [`gpt-image-2.5-flare`](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare) and [`gpt-image-2.5-sunburst`](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst), not a single verified unsuffixed ID. Verify model entitlement and current pricing in the actual deployment account before implementation. Sources: [model catalog](https://developers.openai.com/api/docs/models), [pricing](https://developers.openai.com/api/docs/pricing), [image generation guide](https://developers.openai.com/api/docs/guides/image-generation).

| Workload | Proposed initial route | Escalate / fallback | Published price signal |
| --- | --- | --- | --- |
| Brief extraction, routine summaries, simple candidate explanations | [`gpt-5.6-luna`](https://developers.openai.com/api/docs/models/gpt-5.6-luna), with a strict output schema and app validation | [`gpt-5.6-terra`](https://developers.openai.com/api/docs/models/gpt-5.6-terra) for ambiguous constraints or difficult source reconciliation; [`gpt-5.6-sol`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) only if measured gains justify it | Luna $0.20 input / $1.20 output per 1M text tokens; Terra $2 / $12; Sol $4 / $20. Cached-input rates and long-context premiums differ. |
| Multi-source research reasoning | Luna with lawful source tools and a source ledger; humans can inspect each citation | Terra for conflicting specifications and uncertain variant matches; source gaps return S09/S12 rather than a guessed answer | Text tokens **plus** any tool/search charges and source costs; budget per job. A more capable model cannot create missing retailer rights or stock evidence. |
| Product-in-room image edit | [`gpt-image-2.5-flare`](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare) for first candidate render, subject to real-SKU identity/fit evaluation | [`gpt-image-2.5-sunburst`](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst) when edit precision requires it; source-photo/measurement fallback if quality or rights fail | Both list $5/1M text-input tokens, $8/1M image-input tokens, $30/1M image-output tokens. **Cost per image is not established by those rates alone**; quality, size and token usage matter. |
| Short push-to-talk utterances | [`gpt-transcribe`](https://developers.openai.com/api/docs/models/gpt-transcribe), then Luna intent extraction; visible correction before saving | Text/manual input on permission or network failure | $0.0045 per minute of transcription audio. |
| Responsive hands-free voice | [`gpt-realtime-2.1-mini`](https://developers.openai.com/api/docs/models/gpt-realtime-2.1-mini) only when duplex latency/barge-in matters; preserve stop/correct/undo in app UI | Turn-based transcription + [`gpt-4o-mini-tts`](https://developers.openai.com/api/docs/models/gpt-4o-mini-tts); manual text | Realtime mini: $0.60/$2.40 per 1M text input/output tokens and $10/$20 per 1M audio input/output tokens. Mini TTS: $0.60/1M text input and $12/1M audio output tokens. [`gpt-live-transcribe`](https://developers.openai.com/api/docs/models/gpt-live-transcribe) is a separate low-latency transcript option at $0.017/min. |

The default is a cost hypothesis, not a quality conclusion. For a *hypothetical* 10,000 text-input and 1,000 text-output token request, published uncached token rates imply about **$0.0032 Luna**, **$0.032 Terra** or **$0.060 Sol**, before tool, image, cache-write and other charges. Real request distributions and success/retry rates decide cost per useful recommendation. Run fixture-based evaluations on real chair variants, quantity/stock ambiguity, hard-cap math, fit, source conflicts, voice correction and client privacy. Promote a more expensive route only if it materially improves an acceptance gate or lowers total cost through fewer retries. Track dollars/project and dollars/verified usable candidate, not token price alone. OpenAI’s [model guidance](https://developers.openai.com/api/docs/guides/latest-model) and [model pages](https://developers.openai.com/api/docs/models) can change; recheck at build and release time.

## Interaction and reliability choices

Use ordinary streamed text/status events for S08 findings and S10 briefings; use a dedicated realtime session only for simultaneous listening/speaking and interruption. OpenAI documents [streaming Responses](https://developers.openai.com/api/docs/guides/streaming-responses), [background mode](https://developers.openai.com/api/docs/guides/background), and [voice-agent patterns](https://developers.openai.com/api/docs/guides/voice-agents). Homely’s own queue and event log remain authoritative for long research, monitoring and image jobs, cancellation, idempotency and user-facing progress. Provider-specific async handles can be stored as worker metadata. A provider outage or unsupported capability yields a typed failure and a manual/source-evidence path.

Keep API keys server-side; isolate user/tenant assets; enforce pro/client scopes before retrieval, rendering or sharing. Keep originals and audit trails under a stated retention/deletion policy. Record source terms and image rights. Meter rate limits, retry/backoff, circuit breaks, timeouts and worst-case cost. Evaluate provider/prompt changes offline, canary them on bounded traffic, then rollback on quality, latency or budget regression. Do not rank products by commission.

## UX-to-architecture trace

| UX path | Architecture page and gate |
| --- | --- |
| S04→S07 voice/correction | `04 VOICE`: consent, mode, transcript, typed patch, correction and portable history. |
| S07→S08→S09/S10 research and hunt | `02 SOURCE + STOCK` and `05 JOBS`: lawful source adapters, partial progress, empty/gap state and bounded monitoring. |
| S10→S11/S12 exact variant | `02 SOURCE + STOCK`: identity, six-unit evidence, source time and lead separation. |
| S11→S13→S14 visualize and swap | `03 ACTUAL PRODUCT IN ROOM`: source lineage, async image edit, identity/geometry gates and fallback. |
| S14→S16→S17/S18 choose and buy | `00 CORE`/`02 SOURCE + STOCK`: all-in hard-cap gate, fresh stock/price recheck and external handoff. |
| S16→S20/S21 client and purchase history | `00 CORE`: scoped review and app-owned decision ledger. |

**Open decisions:** approved source integrations and stock verification method/expiry; image rights and tested fidelity threshold; measurement protocol; privacy/retention defaults; initial voice mode; monitoring cadence and cost ceiling; model availability and account spend limits; client sharing permissions; affiliate terms. The architecture routes around uncertainty but cannot settle these product and commercial choices itself.
